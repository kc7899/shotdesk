# Shotdesk API workflow

Read [AGENTS.md](/AGENTS.md) for the current operating rules. Discover live fields through `/api/shot-schema`, `/api/asset-schema` and `/api/agent-info`. Write requests use JSON. Read the latest project before editing; do not reuse IDs from old conversations.

1. **Project and script:** GET/POST `/api/projects`, GET `/api/projects/<pid>`, POST `/api/projects/<pid>/save` for partial updates. `/plan` generates only a script. Obtain review before extracting assets.
2. **References:** POST project `/extract-assets`, then explicitly confirm candidates through `/apply-extracted-assets`. Clothing variants belong to the character's `looks`. Keep identity images, outfits and voice samples separate.
3. **Storyboard:** GET `/api/storyboard-skill?project_id=<pid>` for the current `h3-structured-v2` instructions. POST project `/storyboard` with `{"stage":"all"}`. Replacing existing shots requires user authorization and `replace_existing:true`. Do not inject historical storyboard instructions.
4. **Asset bindings:** Use stable `asset_ids` and `character_looks` IDs. `@label` binds through `prompt_mentions[label]={asset_id,look_id}`. Preview actual `image_inputs`, `reference_bindings` and `compiled_prompt` through project `/preview-prompt`. A name in prose alone does not supply an image.
5. **Generation:** POST project `/generate` with `{"target":"shot","id":"actual-shot-id","kind":"image"}` or `"video"`. `/generate-batch` adds another round on every call; do not repeat without authorization. Follow project defaults or per-shot overrides. Reference-to-video does not require a first frame.
6. **Progress and stopping:** GET `/api/jobs` or project `/jobs`. POST project `/jobs/<jid>/stop`, or `/api/jobs/stop-all`. Never clear other clients' shared ComfyUI tasks. Stopping does not mean resources have already been released.
7. **Inspection:** Fetch the actual media. Prompts, filenames and metadata are not visual evidence. Remote server paths are not local file paths. Inspect video and audio directly. Versions are ordered newest first by `created`; identify them by stable `id`/`url`, not array position.
8. **Read and completion:** Project `/read-media` or `/consume-media` takes `version_ids`. A blue dot means unread, not failed review. Human and Agent share read state. `/shot-completion` takes `{shot_id,kind,completed}` and records production completion separately.
9. **Export:** Select versions, then POST project `/compose`. A project JSON export is not a full media backup; back up the data volume as well.

GET/POST `/api/settings` manages sanitized connection settings; `/api/settings/test` checks a connection. Never put secrets in project prompts or exports. Workflow import uses `/api/workflows/import {workflow,replace:false}` and dependency checks use `/api/workflows/check {id}`. Generic import requires the portable adapter and explicit parameter mappings; it does not install weights or verify generation quality.

With access protection enabled, supply a Bearer password/token or login cookie. Clear shots/assets only with explicit authorization, current `confirm_name`, `expected_updated` and reset epochs. Deleting a project keeps it in Trash for seven days.

Interface language (`shotdesk.uiLanguage` in the browser) is independent of the project's `prompt_language` (`zh`/`en`). Changing the interface does not translate scripts, prompts, asset names or API enum values. Preserve original dialogue and user-authored content.

## Cloud video providers

Read the redacted `video_providers` array from `/api/settings`. Configure providers through the guarded settings endpoint with stable `id`, `name`, `protocol` (`ark`, `minimax`, `replicate`, `fal`), `url`, actual `model`, private `api_key`, native `resolution`, `max_references`, `modes` and `enabled`. Preserve other entries when replacing the array. Blank keys retain existing secrets; `clear_key:true` removes them. Choose the returned `cloud-<id>` from the model catalogue, then use the same generation and preview APIs as local workflows. The official full-quality H3 model is `MiniMax-H3` over MiniMax V2, 768P/2K, integer 4–15 seconds. Cloud supports text, first-frame and image references. Ark reference mode additionally accepts explicit shot flags cloud_use_audio/cloud_use_video, using audio_source/reference_audio and reference_video. Audio uses data URLs. Video requires the profile public_media_url (public HTTPS studio base URL); the platform creates six-hour single-file signed links, without exposing the media directory or configuring a tunnel. Other protocols still reject audio/video reference inputs. Last frames remain unsupported. Each fal endpoint must declare its actual single generation mode.

Cloud task IDs are persisted for restart recovery; never resubmit an ambiguous paid request automatically. A running official H3 task cannot immediately be cancelled. Keep cancellation pending until upstream termination is confirmed; billing may continue. Configured and mock-tested do not mean live-generation verified.

## Help users find provider settings

Confirm official provider versus gateway first. For Ark use `https://ark.cn-beijing.volces.com/api/v3`, keys at https://ark.volcengine.com/region:cn-beijing/apikey, and actual model IDs from https://console.volcengine.com/ark/region:cn-beijing/overview or the model's API example. For MiniMax use `https://api.minimax.io`; sign in at https://platform.minimax.io → API Keys for pay-as-you-go video, and consult https://platform.minimax.io/docs/api-reference/video-generation-v2-create (`MiniMax-H3` is the full-quality model). Replicate uses `https://api.replicate.com/v1`, tokens at https://replicate.com/account/api-tokens and IDs from model pages. fal uses `https://queue.fal.run`, keys at https://fal.ai/dashboard/keys and endpoint IDs from https://fal.ai/models. Gateways supply their own URLs, IDs and keys; verify the declared protocol. Never ask users to disclose keys in chat. Preserve existing settings. `public_media_url` is the user's public HTTPS Shotdesk URL, never a provider API URL; it is needed for Ark video references or virtual character library sync.

## Experimental Ark AIGC asset sync

After the user signs the official virtual-asset agreement and enables the required entitlement, configure private `asset_access_key`, `asset_secret_key`, `asset_project` and public HTTPS `public_media_url` on the official Ark profile. These credentials differ from the video API key and are never returned by settings. POST `/api/projects/<pid>/sync-ark-asset` with `model:cloud-<id>` and `resource_id:<character-or-look-id>` to enqueue asset_sync. GET `/api/projects/<pid>/ark-assets` for states. The workflow creates an AIGC group per character, uploads each identity/look image, and polls review; existing IDs are queried without reupload. Only Active is usable. Unknown submissions require reconciliation rather than automatic retry. Mappings live in the project's ark-assets.json; changed images invalidate old approvals. Ark generation uses approved asset:// references, while local and H3 paths stay unchanged. No live review has yet been verified; local mock tests are not approval evidence.

## Seedance asset picker
Use “Select Seedance asset” on an identity/look card to register a name, asset ID/URI and an optional project-local thumbnail. No AK/SK or public media URL is required for manual registration; both existing settings remain available for automatic sync. Public-library IDs can be used after enabling the account entitlement and accepting the terms. Private IDs require access rights.
GET /api/projects/<pid>/ark-assets returns resources and catalog. POST /manage-ark-asset with model:"cloud-<id>" and operation: register (name,asset_id,thumbnail?), bind (resource_id,catalog_key), unbind (resource_id), remove (catalog_key; unbind first). Upload the matching image to the identity/look before binding. Manual status means user-provided, never remotely verified Active. IDs are sent through the normal generation queue; image changes invalidate bindings. Local/H3 references remain unchanged. This is a locally registered list, not automatic remote enumeration; official ListAssets requires AK/SK.
As of 2026-11-02, Ark also trusts same-account original face images from Seedream 5.0 lite/pro/flash text-to-image within 30 days, plus eligible Seedance 2.0/2.5 original videos and their final frames, subject to activation dates. Not every Ark model or edited image qualifies. Preserve original bytes; editing, compression or forwarding can break trust. Trust does not guarantee output approval. See https://docs.volcengine.com/docs/ark/seedance-portrait-asset-guide?lang=zh .

## Per-shot preparation
POST /api/projects/<pid>/prepare-shots with operation assets / prompts / prepare / prepare_video, scope missing (default) / all, optional shot_ids. Omitted IDs select every shot. prepare_video requires confirm_generate:true and may incur charges. Default prepare only matches existing assets and writes prompts from each editable description, never reuses old plans as the source or submits media. Identity/look ownership and actual IDs are validated. Manual results are preserved unless scope=all; automatic fingerprints allow changed inputs to be recomputed and partial completion to be resumed. Manual edits to automatic results are preserved.
Use normal jobs/stop APIs. Read preparation_progress, preparation_results, result.failed and result.needs_review: task completed is not an assurance that every shot succeeded or passed quality review. Every step commits independently; one shot failure does not block others. Concurrent edits prevent overwrite. prepare_video skips existing videos, blocks shots with review warnings, and generates/waits for missing first frames in first_frame mode before video. Other driving inputs must already exist. Parent cancellation attempts to stop its current child job; upstream cancellation limitations still apply. Query child_job_ids before retrying interrupted media work. No description, duration or existing media is deleted. Existing orphan references may be saved unchanged without blocking unrelated asset edits; new broken references/deleting referenced assets remain rejected.
